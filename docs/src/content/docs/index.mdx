AeroCMS combines ASP.NET Core, Razor and Blazor manager UI, source-generated module registration, Orleans application boundaries, Sable/SurrealDB-backed persistence, and several constrained page-rendering strategies. It is useful when a .NET team wants runtime-managed content without adopting a client-side SPA as the application shell.

## Documentation trust model

These pages were verified against commit `ece0dc3915de1005fba89357f4957830a963206e`. Behavior claims come from current source, configuration, and tests. Older material under the repository's historical `docs/` and `.docs/` collections is not automatically treated as implemented behavior.

This public corpus intentionally excludes:

- documentation for the `Aero`, `AeroDB`, `AeroVault`, `NeoUI`, `craft.js`, `hyperui`, `tiptap-dotnet`, and `ui` Git submodules;
- generated files, `bin/`, `obj/`, and legacy Marten reference code;
- credentials, connection strings, customer data, PII, and security-sensitive runbooks;
- proposals that cannot be verified in current code.

Use the [feature inventory](/concepts/feature-inventory/) to see the evidence chain and the [coverage report](/reference/coverage/) to see what remains incomplete.
